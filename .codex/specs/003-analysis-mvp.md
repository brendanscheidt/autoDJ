## Purpose

Start Phase 3 by replacing the single-file analysis stub with a manifest-aware
batch analysis workflow. The first implementation slice should consume the
repository manifest produced by spec 002, write `analyzed-track.json` artifacts
into the metadata cache layout, skip valid up-to-date artifacts, and use
`ffprobe` to populate basic audio container/stream metadata.

This spec should make analysis cache behavior real before attempting hard music
intelligence. BPM, key, beat grid, sections, energy, vocals, cue points, and
stems can remain explicitly low-confidence placeholders in this slice.

## Goals

- Add `autodj-analysis analyze-batch <repository-manifest.json> --out <cache-root>`.
- Read repository manifests generated by `LocalAudioRepository`.
- Write one `analyzed-track.json` per track under
  `<cache-root>/tracks/<track-id>/`.
- Use `ffprobe` for real duration, sample rate, channel count, codec, bit rate,
  format name, and tag metadata where available.
- Preserve repository `TrackAsset` identity fields in the analyzed artifact.
- Use track ID, source content hash, analyzed-track schema version, analyzer
  producer/version, and parameters hash to skip up-to-date artifacts.
- Continue processing other tracks when one track fails.
- Return and print a batch summary with analyzed/skipped/failed counts.
- Keep generated artifacts compatible with `analyzed-track.schema.json`.
- Update README status and usage docs so the repo no longer describes itself as
  only foundation setup.

## Non-goals

- No BPM detection beyond explicit low-confidence placeholders.
- No key estimation.
- No real beat grid, downbeat, section, energy, vocal, cue, or stem analysis.
- No waveform generation.
- No Demucs or stem separation.
- No Essentia/librosa integration yet.
- No C++ playback, DJ strategy, or desktop UI changes unless a narrow docs/build
  update is needed.
- No SQLite.
- No real audio fixtures committed to git.

## Required Deliverables

### Batch CLI

Add:

```powershell
.\.venv\Scripts\python -m autodj_analysis analyze-batch <repository-manifest.json> --out <cache-root>
```

Recommended options:

- `--ffprobe <path>`: override executable path, default `ffprobe`.
- `--force`: rewrite artifacts even when cache validation says they are current.
- `--parameters-hash <hash>`: optional deterministic override for experiments;
  default to the implementation's current probe/stub parameter hash.
- `--json`: print machine-readable batch summary.

The CLI should exit:

- `0` when every track was analyzed or skipped successfully.
- Nonzero when manifest loading fails, `ffprobe` is unavailable, or one or more
  tracks fail. The summary should still list successful/skipped tracks.

### Repository Manifest Reader In Python

Add a small Python reader for `repository-manifest.json`.

Minimum behavior:

- Validate required top-level fields used by analysis.
- Recover `repositoryId`, source metadata, track list, track IDs, source URIs,
  content hashes, and format hints.
- Reject missing or malformed required fields with actionable errors.
- Do not depend on the C++ repository code at runtime.

### Cache Path Resolution

Mirror the spec 002 cache layout:

```text
<cache-root>/
  tracks/
    <track-id>/
      analyzed-track.json
```

The Python worker may have its own path helper, but it must produce paths
compatible with `MetadataCachePaths`.

### FFprobe Integration

Use `ffprobe` through a subprocess boundary.

Recommended command shape:

```powershell
ffprobe -v error -print_format json -show_format -show_streams <audio-file>
```

The implementation should:

- Parse JSON output.
- Select the primary audio stream.
- Populate duration from stream or format metadata.
- Populate sample rate and channels from the audio stream.
- Populate codec and format metadata under `source.providerMetadata`.
- Surface clear structured per-track errors for missing files, missing audio
  stream, invalid JSON, missing executable, or nonzero ffprobe exit.

### AnalyzedTrack Artifact

Write `analyzed-track.json` atomically.

Real fields in this slice:

- `trackId`
- `source.trackId`
- `source.repositoryId`
- `source.sourceUri`
- `source.contentHash`
- `source.title` when available or derived from filename
- `source.durationSeconds`
- `source.sampleRate`
- `source.channels`
- `source.formatHint`
- `source.providerMetadata.ffprobe`
- `analyzer.producer`
- `analyzer.producerVersion`
- `analyzer.createdAtUtc`
- `analyzer.sourceContentHash`
- `analyzer.parametersHash`
- top-level `durationSeconds`

Placeholder fields in this slice:

- tempo should be explicit low-confidence, not falsely accurate.
- key should remain unknown with confidence `0.0`.
- beat grid/downbeats should be empty or minimal low-confidence placeholders.
- sections should be empty or unknown low-confidence placeholders.
- energy/vocals/cue points should remain placeholders with warnings.

Artifacts must include a quality warning such as:

```text
Only ffprobe metadata was analyzed; musical analysis is not implemented yet
```

### Cache Validation

Before writing, inspect an existing analyzed artifact.

Skip when all of these match:

- artifact `schemaVersion`
- artifact `trackId`
- artifact `analyzer.producer`
- artifact `analyzer.producerVersion`
- artifact `analyzer.sourceContentHash`
- artifact `analyzer.parametersHash`

Rewrite when any value differs, when JSON is malformed, or when `--force` is
set.

### Tests

Use pytest and generated temporary files only.

Recommended tests:

- Manifest reader accepts a minimal repository manifest.
- Manifest reader rejects malformed/missing required fields.
- Cache path helper resolves `tracks/<track-id>/analyzed-track.json`.
- FFprobe runner parses representative JSON.
- FFprobe runner reports executable and nonzero-exit failures.
- Single-track analysis writes probed duration/sample-rate/channels.
- Batch analysis writes one artifact per manifest track.
- Batch analysis skips up-to-date artifacts.
- Batch analysis rewrites stale content-hash or analyzer-version artifacts.
- Batch analysis preserves successful tracks when another track fails.
- CLI `analyze-batch --json` emits a useful summary.

Tests should fake `ffprobe` output with a tiny script or test double where
possible. Optional integration tests may use a generated WAV fixture only when
`ffprobe` is available locally, but those tests must skip cleanly when it is not.

## Acceptance Criteria

- `analyze-batch` reads a repository manifest and writes analyzed artifacts
  under the metadata cache layout.
- Existing up-to-date artifacts are skipped deterministically.
- Modified source content hashes trigger artifact rewrite.
- `ffprobe` populates real duration/sample-rate/channel/codec metadata.
- BPM/key/sections remain clearly marked as unimplemented or low-confidence.
- Per-track failures do not discard successful artifacts.
- Python tests pass.
- Existing C++ tests still pass.
- README documents current repo status and the new analysis commands.
